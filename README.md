# RebirthProjectMU

MU Online client + server source (Season 5.2~6.3), `Source_Client` (C++/OpenGL) and `Source_Server` (DataServer, JoinServer, ConnectServer, GameServer).

## Changelog

### 2026-08-17
- **Revert**: Lorencia (`World1`) terrain and tiles restored to the original MU assets — reverts the customized tiles/terrain that had been in place, plus a full set of the stock `EncTerrain1`/`Terrain`/tile (`.att`/`.map`/`.OZJ`/`.OZT`) files.
- **Feature**: `BauSelector.lua` — a "SELECIONAR BAU" panel (Panel9 stone/gold frame, title + "Bau atual: N" subtitle, 11-button 0-10 grid with the current vault highlighted) replacing the plain-text `Warehouse.lua` picker as the client-side UI for the existing `/bau <num>` + `/abrirbau` commands; reuses that script's already-verified command-sequencing logic (chat-cooldown polling, "no interface open" guard) unchanged.
- **Feature**: two new client Lua bindings, `DrawTextCentered`/`DrawTextBigCentered` (`ClientLuaFunction.cpp`) — exact text centering via the engine's own `RT3_SORT_CENTER` layout (`RenderText()`'s box-width/sort params) instead of a guessed character width, and a 2x bold font (`g_hFontBig`, already created at startup but never exposed to Lua) for standout labels like a digit grid.
- **Feature**: reusable `Panel9.lua` 9-slice panel helper (`Lua-Source/System/Panel9.lua`) for custom Lua UI windows — `Panel9.Draw`/`Panel9.DrawCentered(x/w, y/h, cornerSize, skin, colors)`, with a single-fill fast path for a single photographic panel texture (stretched whole, no seam) and a flat-color fallback for skin fields with no art yet. `Panel9Demo.lua` is the reference consumer (toggle button, real Midjourney-sourced stone/gold skin, functional close button, drag-and-drop-placed extra elements).
- **Feature**: `Tools/ImageConverter/png_to_mu.py` / `remove_bg.py` / `mu_decode.py` — convert any Pillow-readable image to/from this client's `.OZT`/`.OZJ` formats (spec reverse-engineered from `GlobalBitmap.cpp`, round-trip verified), plus a connectivity-aware (flood-fill) background remover for "isolated on black" Midjourney source art that preserves legitimately-dark enclosed design areas.
- **Feature**: `Tools/PanelDesigner/panel_designer.py` (+ packaged standalone `Panel9LayoutDesigner.exe`) — a visual editor for laying out a `Panel9`-based window (drag assets onto background/close-button/canvas to create buttons, resize, undo history, live-generated Lua) and saving straight into `Panel9Demo.lua`, instead of hand-editing coordinates.

### 2026-08-16
- **Fix**: client Lua's `LoadImage()`/`RenderImage()` rendered a plain white square for any non-power-of-2 `.OZJ`/`.OZT` UI image (e.g. `whare_off.ozj`, `newui_Bt_Warehouse.OZT`) no matter what was tried - real root cause was `Bitmaps.LoadImage()` returning `BITMAP_UNKNOWN` (`_TextureIndex.h`: `= 30000`, *not* `0`) on a failed load attempt; the code was checking `slot == 0`, so a failed `.jpg` try was never detected and the client's placeholder "unknown texture" got drawn and stretched instead. Two earlier real issues surfaced and got fixed along the way to get here: `RenderBitmap()` doesn't enable `GL_BLEND` on its own (`EnableAlphaTest()`/`DisableAlphaBlend()` now wrap the draw), and non-power-of-2 source art gets padded to the next power of 2 at load time with uninitialized memory, not transparency (native code crops this with a literal UV fraction, e.g. `24.f/32.f` - see `UIControls.cpp`/`ZzzInventory.cpp`'s `BITMAP_INVENTORY_BUTTON`).
- **Feature**: `LoadImage(path)` no longer needs a `.jpg`/`.tga` extension, or even to know which one an asset actually is - it tries both real on-disk formats (`.OZJ`/`.OZT`) itself and uses whichever exists. It also measures the image's real (pre-padding) size and returns it (`uWidth`, `vHeight`); `RenderImage(id, x, y, w, h)` looks this up automatically and crops accordingly, so scripts never need the `24.f/32.f`-style manual math native code uses.
- **Chore**: `Lua-Source/encrypt_lua.py` now deploys the encrypted `.enc` straight to `Global Debug\Lua\` instead of dropping it next to the source and requiring a manual copy step (`--local` still available for a loose copy alongside the source, rarely needed).

### 2026-08-15
- **Feature**: Lua scripting engine embedded in the GameServer (`ScriptLoader`/`LuaFunction`, ~170 native bindings covering objects, items, monsters, guilds, commands, effects, messages), ported from a compatible SSeMU-lineage pack and adapted to this project's real API surface. Vendors Lua 5.2 (headers + a prebuilt `lua52.lib`). Scripts live under `MuServer/Data/Script/` (`ScriptMain.lua` → `System/ScriptCore.lua` core dispatcher + individual scripts); a new `Script\WindowTitle.lua` sets the client's window title to `Player: <nick> || Level: <level> || Reset: <reset>` on character entry, using a new `SetObjectWindowTitle` Lua binding and a matching new client↔server packet (`0xC1:0x74`).
- **Fix**: the window title (above) only refreshed at login, so leveling up mid-session left it showing a stale level. Added a proper `OnUserLevelUp` script hook (fires the instant `CharacterLevelUp` succeeds) instead of relying on login-only data. Confirmed fixed in-game.
- **Feature**: GameServer console menu — `Recarregar → Recarregar: Script`, reloads just the Lua scripts (`ScriptMain.lua` and everything it requires) without touching any of the other `Recarregar: *` categories. `Recarregar Todos!` already covered this since scripts reload as part of `ReloadAll()`.
- **Feature**: a second, independent Lua scripting engine embedded in the client (`Source_Client`) - `ClientScriptLoader`/`ClientLuaFunction`, hooked into the real per-frame UI update/render loop (`g_pNewUISystem`'s `Update()`/`Render()` in `ZzzScene.cpp`). Scripts live under `Lua-Source\` (tracked source) → built into `Global Debug\Lua\` (deployed). First script (`TestButton.lua`) draws a clickable text button and posts a chat message on click - confirmed working end-to-end in-game.
- **Feature**: client Lua scripts ship encrypted (`.enc`, XOR + a magic header - the same protection tier as this client's `.bmd` data files) instead of as plain `.lua`, so the deployed client folder doesn't leak readable script source. `ClientScriptLoader` loads `.enc` if present, falling back to a plain `.lua` for local dev iteration. `Lua-Source/encrypt_lua.py` is the build step; see `Lua-Source/README.md`.
- **Feature**: multi-warehouse UI (`Lua-Source/Warehouse.lua`) - built entirely on top of `/bau <num>` and `/abrirbau`, two GameServer commands (`CommandManager.cpp`) that turned out to already be fully implemented and configured (per-account-level vault limits, an `ExtWarehouse` DB table, the whole DataServer round trip) but never had a client UI and were easy to miss since command registration in this file is data-driven, not the commented-out `this->Add(...)` calls next to each one. A small `[Trocar Bau]` trigger (only shown while the warehouse is closed, since `/bau` refuses to run while any interface is open) opens a 0-10 picker; picking a number sends `/bau N` then `/abrirbau` once the chat cooldown actually clears - opens the chosen vault from anywhere, no NPC needed. Added a handful of new client Lua bindings along the way: `DrawPanel` (flat background, reusing `NewUIMuHelper`'s own `RenderColor` primitive), `ConsumeClick` (stops a UI click from also moving/attacking - has to clear both `MouseLButton` and `MouseLButtonPush`, `ZzzInterface.cpp`'s `Attack()` checks either), `GetChatTime` (polls the real `SendChat()` cooldown instead of guessing a fixed wait).
- **Feature**: raw SQL access from server-side Lua scripts (`SQLConnect`/`SQLQuery`/`SQLFetch`/`SQLGetNumber`/`SQLGetString`/etc, 10 bindings) - restored by porting `QueryManager.cpp/h`, a standalone ODBC connection class, straight from this project's own DataServer (it already has this exact class for its own use). Connects once at startup from `GameServerSQL.ini` (`[SQL] ODBC=/USER=/PASS=`, not tracked in git); if that file is missing or empty, SQL is just unavailable to scripts - everything else still starts up fine.
- **Feature**: `MuServer/Data/Script/System/ScriptDefine.lua` - named constants (`ObjectType.OBJECT_USER` instead of a bare `1`) for the ~180 native Lua functions, covering objects, items, effects, maps, messages, and now `SQLResult` too. Sourced from a community-maintained list for this SSeMU-lineage Lua API, trimmed to what applies here.
- **Feature**: MU Helper auto-play engine ported in full (attack, heal, buff, drain life, item pickup/filtering, equipment repair, party support, combo skills, self-defense), with a gear/play icon pair on the position HUD and a `Z` hotkey to open it.
- **Feature**: MU Helper config (skills, range, repair, pickup filters, thresholds) now persists across logins, server-side — reused this pack's existing but previously client-unused `HelperData` DB pipe (`0xC1:0xAE`/`0xC1:0x17`) instead of a bespoke mechanism.
- **Fix**: MU Helper's repair-item check flooded a request every 250ms tick during combat — throttled to once every 5s.
- **Fix**: MU Helper's "Pick All Near Items" / "Pick Selected Items" were only visually mutually exclusive — the underlying flags never actually cleared, so it kept picking up everything regardless of the UI.
- **Fix**: closing MU Helper left its skill-picker sub-window open (`CNewUIObj::Show()` isn't virtual, so the generic window-close path couldn't reach the override that closes it).
- **Fix**: MU Helper's "Add Extra Item" truncated names to 14 characters (e.g. "Scroll of Hellfire" → "Scroll of Hell") — two separate leftover buffers, both from a dropped older protocol format.
- **Fix**: MU Helper's saved-item list couldn't select any line but the first, and allowed duplicate entries.
- **Fix**: MU Helper's Auto Potion/Heal/Party-Heal threshold bars reset unless closed via the exact right button.
- **Fix**: Dark Spirit pet never actually attacked in any mode — was sending the raw command enum value instead of the small index the server expects.
- **Fix**: several skills (Twisting Slash, Evil Spirit/Storm, and ~30 others across every class) dealt damage via MU Helper but never played their animation — ported each one's real client-authoritative packet sequence from its own source location.
- **Fix**: MU Helper's basic attack ignored the character's actual attack speed, attacking every 250ms tick regardless of Agility — now paced using the same animation-duration data the game itself uses to play the swing.
- **Fix**: skill names (character skill list tooltip) were in Portuguese in *both* the Portuguese and English clients — translated all 365 to English in both.
- **Fix/Translation**: Command Window (`D` key), several item-stat tooltip lines (e.g. "Reflect Damage"), a few special-item descriptions, all 158 buff names/descriptions, and the Guild creation prompt were in English in the Portuguese client — translated to Portuguese.
- **Feature**: screenshots (`PrintScreen`) now save into a `Screenshots\` folder (created automatically if missing) instead of the client's root, and the filename now includes the character's nickname.
- **Chore**: stopped tracking `Source_Client/Global Debug/Main` — it was a stale 19MB `.ilk` (incremental linker database) file mistakenly committed instead of the real `Main.exe` (it dodged the `.gitignore`'s `*.exe`/`*.ilk` rules by having no extension). The real `Main.exe` stays untracked, as it already was.
